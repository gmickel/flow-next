# Conduct checklist — /flow-next:make-pr

A correct run on a spec branch authors a grounded aid artifact, renders its briefing through flowctl, and opens the PR via `gh`. On a branch without a spec it opens the PR directly with the session's handoff as the body.

- [ ] Claims trace to the export payload, task evidence and review receipts. Missing attribution stays honest; raw diff code is not quoted. Verification marks pass only from a gate that ran green; failed, inconclusive, and unrun gates stay explicit.
- [ ] On a real create with all tasks done and no pending completion review (`completion_review_pending`), the spec-close commit exists before export and aid composition, and a failed close stops the run. Incomplete or task-less specs, and specs with a pending completion review, compose without closing; autonomous runs with open tasks or a pending review stop; dry-run and body-only updates never close.
- [ ] The structured aid runs on every spec invocation, including `--dry-run`; flowctl renders the body and invalid or stale artifacts use the labeled fallback without mixing their fields into it. A diff over 500 changed files skips composing and writes that fallback in the briefing's section order, with a bulk mechanical commit named in one Review focus sentence. A run that composed an oversized artifact first has broken this. `--dry-run` prints the body and stops before push, PR creation, or a spec-close commit.
- [ ] The PR opens ready unless `--draft` was passed or open items exist (spec open questions, a pending completion review, incomplete tasks, open findings on a `NEEDS_WORK` or `BLOCKED` QA receipt, a call left for the person); on the no-spec path, an open item in the handoff drafts it too. Follow-ups and deferred findings are listed in the body and never make the PR a draft. A draft opened only because follow-ups exist has broken this.
- [ ] The PR is created without a confirmation gate; questions only resolve information that cannot be derived, such as the spec or base ref. Autonomous runs never prompt.
- [ ] A branch without a spec (preflight exit `NO_SPEC`, or no `.flow/`) takes the no-spec path: a new branch when on the default branch, the handoff (what changed, how it was verified, open items and follow-ups) as the body file, `gh pr create` (or `gh pr edit` under `--update`), and the PR URL printed. No spec is created, and no later phase runs. A run that minted a spec to open a PR has broken this.
