# Conduct checklist - /flow-next:land

A run resolves and lands one named pull request under current session authorization. The skill and its workflow own the detailed gates; this checklist checks their observable boundaries.

- [ ] Exactly one terminal `LAND_VERDICT=<verdict|NO_WORK> prs=<n> pr=<url|-> reason="<one line>"` is last. `RELEASED` is never emitted. The named resolved PR uses `prs=1`; no resolved target uses `prs=0 pr=-`. Missing or ambiguous input stops with its reason; a closed-unmerged PR is never replaced, reopened, or merged; the run asks no questions and invokes no driver.
- [ ] Land reads specs at the full remote PR head and selects by `branch_name == headRefName` (falling back to specs done at the head but not at the base); the selected set must be nonempty and closed, and a failed or truncated read is never an empty set.
- [ ] Repairs need no merge authorization; merging does. Threads dispatch autonomous resolve-pr before CI repair; a code CI failure gets one fix and a flake one rerun, never the same budget twice; behind branches catch up server-side. Land never rebases, force-pushes, retargets, or checks out a branch in the invoking checkout; conflicts stop with the branch needing a rebase.
- [ ] Merge requires current authorization for this PR, green checks, a nonblocking review decision, and zero unresolved threads; a flow-authorized merge without human in-session authorization waits `land.patienceMinutes` after the last push, except a goal run's child PR whose observed base is that goal's `goal/<name>` integration branch, and a configured `land.mergeVerdictCommand` that fails refuses the merge. The squash merge is pinned to the full current head SHA; a moved head is re-read and reported, never silently substituted.
- [ ] Stacks: only the lowest open layer merges, a branch still targeted by an open PR is retained, and where stacks are unavailable a conflicted child is reported as needing a manual rebase with no local cascade.
- [ ] After merge, land writes no repository file, commit, or push; a failed tracker touchpoint reports the merge commit and keeps `MERGED`. `--dry-run` reads and reports only: no repair, catch-up, stack creation, verdict command, merge, branch deletion, or tracker mutation.
