# Conduct checklist — /flow-next:land

A correct tick discovers the open PRs the build loop authored, walks each through the gate tree, takes at most one action class per PR, and ends on a single terminal verdict line.

- [ ] The last line of the response is exactly one `LAND_VERDICT=<verdict|NO_WORK> prs=<n> pr=<deciding-pr-url|-> reason="<one line>"`, computed by the worst-severity rule across PRs, with nothing printed after it.
- [ ] The tick asks the user nothing; ambiguity is reported as `NEEDS_HUMAN`. A tick that puts a question to the user has broken this.
- [ ] Each PR gets at most one action class, and its gate reads are echoed into the transcript — CI tri-state, patience window, unresolved threads, review signal — because the cadence driver is transcript-blind and reads nothing else.
- [ ] Only PRs carrying both authorship signals are mutated: the branch matches a spec's `branch_name` and the structural authorship probe finds the make-pr machine marker in footer position. Branch-only matches are reported `NEEDS_HUMAN` and left untouched.
- [ ] A merge happens only after every gate passes in-tick and uses `--squash --delete-branch --match-head-commit`; however the merge is executed - directly or through the `FLOW_PR_MERGE_CMD` seam - `gh pr merge --auto` and merge-queue enrollment never appear, the seam covers the merge call only (every other `gh` call stays on the session identity), its stderr reaches the head-race-versus-policy classification verbatim, and merge-conflict hunks are never hand-resolved.
- [ ] The post-merge tail runs spec close (local commit) → release-follow → tracker touchpoint → persist-push, in that order: release-follow and the tracker touchpoint precede the push of the tail's `.flow` commits, and a refused persist rolls back only those commits and affects bookkeeping only — a tick that let a failed push skip release-follow or the tracker touchpoint has broken this.
- [ ] When `land.mergeVerdictCommand` is set, no merge happens without a zero exit from it; a missing, unexecutable, or timed-out command blocks and never skips; `--dry-run` reports `would-run` and executes nothing.
- [ ] When `land.requestReviewers` is set, reviewers are requested at most once per PR per head SHA and only when a human review is the sole missing merge input, via the Phase 3 `request-reviewers` action class (atomic claim → ready flip → author-filtered request → ledger write); unset/empty leaves every gate, action, and ledger write unchanged (`reviewers=off`); `--dry-run` reports `would-request` and mutates nothing.
- [ ] `--dry-run` produces full discovery plus per-PR classification and the aggregated terminal line with zero mutations — no checkout, push, label, merge, resolve-pr dispatch, or ledger write.
