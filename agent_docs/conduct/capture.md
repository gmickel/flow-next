# Conduct checklist — /flow-next:capture

A correct interactive run saves a source-tagged spec after resolving material choices, shows its summary, and offers the saved file for editing. Under `from:flow` the conductor dispatched the run: capture applies the plan-versus-no-plan rule itself and leaves the next step to the conductor.

- [ ] The body is materialized once to a temporary file and consumed by `spec create --plan-file` (or `spec set-plan` on a `--rewrite`); interactive capture writes without an approve-and-write exchange. Autofix without `--yes` allocates nothing. An inferred tally never serves as evidence of user approval.
- [ ] Each saved spec has a compact summary and actual file path; a rewrite shows its diff. The editor offer opens saved files, re-reads user edits, and never restores the temporary body or mints a duplicate. Glossary and readiness consent stay separate questions; saving never starts implementation. Under `from:flow` no `Mark ready?` question is asked. A `from:flow` run that asked about readiness has broken this.
- [ ] Only lines capture authored carry a tag (`[paraphrase]` / `[inferred]` / `[strategy:<track>]`); the user's verbatim words stay untagged. Every untagged criterion, decision, or boundary line is findable in the evidence, and every evidence line quotes something the user actually typed — a fabricated `> user (turn N)` line (process formula, agent narration, tool output) fails the run. Process fences (new-vs-rewrite, ready-marking, "do not implement", the duplicate-scan outcome) never appear in the spec body or `## Boundaries`, under any tag.
- [ ] Refusal conditions fire rather than being worked around: an existing spec without `--rewrite` (an open spec that `specs --refs` lists as branch-only counts), relevant evidence lost to compaction without `--from-compacted-ok`, and a draft or stale chart briefing without a named-D-ID risk override all stop the run. Chart evidence appears as links without source tags, and `flowctl chart link-spec` runs only after a successful create.
- [ ] Capture stages and commits nothing; the user owns when `.flow/` changes land.
- [ ] The spec-level `no_plan` field is written only by `--no-plan` on a user invocation, or under `from:flow` when the plan-versus-no-plan rule resolved to direct; a user invocation without the flag never sets it, whatever the draft looks like. The close prints one `Recommended next:` line per saved spec in `plan-vs-no-plan.md`'s shape (work `--no-plan` by default, plan only on a named positive signal, refine only with a named open decision, never chart), and none under `from:flow`. A capture that inferred no-plan on a user invocation, or printed a command menu, has broken this.
