# Conduct checklist — /flow-next:refine

A correct run asks only the questions whose answers would change what gets built, in rounds, then writes each answer into the section it belongs in. Asking nothing and reporting the spec clear enough to build is a correct run. Under `--scope=research` a correct run asks nothing and resolves the spec's external-library unknowns from docs into one section.

- [ ] There is one interview whatever the lens: a `--scope` value focuses it and is never questioned. Every question asked passes the one test — a wrong guess would build the wrong thing, the code, docs, an experiment, or implementation cannot settle it, and it is the answerer's call. A scope question, a refused unfamiliar lens such as `qa`, a question walked from a topic bank, or an unasked-for success-metric or latency-budget question has broken this.
- [ ] Every question goes through the blocking question tool, and each body carries a stakes sentence, a named recommendation with its rationale, and one confidence tier (`[high]`, `[judgment-call]`, `[your-call]`). Each round asks the whole current frontier, never pairs a question with its own prerequisite, and names an abandoned branch at the next round's opener. A transcript that prints "Question 1: ..." as plain narration has broken this.
- [ ] Codebase-, project-docs-, and experiment-answerable questions are resolved by investigation and logged under `## Resolved via Codebase`, `## Resolved via Project Docs`, or `## Resolved via Experiment` with evidence, instead of being put to the user — an experiment runs automatically only when read-only or fully disposable, and an inconclusive result goes to the user with the data. A stateful experiment run automatically, or a "should we" question answered by grep, has broken this.
- [ ] Skipped questions land under `## Open Questions` with the unconfirmed leaning and an owner hint, never as decided content; with one or more skips, the write-back consent checkpoint is asked before the spec is written. Answers are recorded at the precision given: a preference goes to `## Decision Context`, and a numeric criterion appears only when the user stated the number.
- [ ] Sections no answer belongs in and the auxiliary sections come back byte-for-byte, and acceptance-criteria R-IDs are appended, never renumbered or replaced. The sanctioned changes are deleting a `## Parked unknowns` bullet or an unanchored `## Open Questions` entry this session resolved, whose answer appears in the section that owns it, and flipping an anchored `## Open Questions` entry to `status=answered` with its answer under it.
- [ ] The completion summary reports the question count (zero with "the spec is clear enough to build"), the skip disposition when there were skips, and every section the session changed; for a spec without tasks the next step recommends `/flow-next:work <id> --no-plan` for a ready cohesive spec, with plan only where decomposition is useful.
- [ ] Under `--scope=research`, before any scout dispatch the run says which case applied (skipped with its reason, a delta rerun, `--force`, or the scouts it dispatches); the pass asks no questions and writes only `## Resolved via Research`.
