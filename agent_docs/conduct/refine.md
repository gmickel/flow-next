# Conduct checklist — /flow-next:refine

A correct run asks only the questions whose answers would change what gets built, in rounds, then writes each answer into the section it belongs in. Asking nothing and reporting the spec clear enough to build is a correct run. Under `--scope=research` a correct run asks nothing and resolves the spec's external-library unknowns from docs into one section.

- [ ] No scope question is asked; a `--scope` value, whatever its words, focuses the one interview. A run that asked which pass to run, or refused an unfamiliar lens such as `qa`, has broken this.
- [ ] Every question goes through the blocking question tool, and each body carries a stakes sentence, a named recommendation with its rationale, and one confidence tier — `[high]`, `[judgment-call]`, or `[your-call]`. A transcript that prints "Question 1: ..." as plain narration has broken this.
- [ ] Each round asks the whole current frontier and never pairs a question with its own prerequisite; when an answer prunes a sub-tree, the next round's opener names the abandoned branch.
- [ ] Codebase-, project-docs-, and experiment-answerable questions are resolved by investigation and logged under `## Resolved via Codebase`, `## Resolved via Project Docs`, or `## Resolved via Experiment` with file:line, path, or experiment evidence, instead of being put to the user — an experiment-answerable fork (behaviour, timing, layout, output, performance, whether an eval separates two options) gets a throwaway experiment, logged with the question, what ran, what was observed, and the decision — but only when the experiment is read-only or fully disposable; a run that auto-executed a stateful, destructive, or external command (a migration, a deployment, a write API) as an experiment instead of taking the blocking question path has broken this, and so has an inconclusive result recorded as a decision instead of going to the user with the data. A "should we" question answered by grep has broken this too, in the other direction.
- [ ] Skipped questions land under `## Open Questions` with the unconfirmed leaning and an owner hint, and the agent's recommendation is never written into a spec section as decided content; with one or more skips, the write-back consent checkpoint is asked before the spec is written.
- [ ] Sections no answer belongs in and the auxiliary sections come back byte-for-byte, the read-back names every section the session changed, and acceptance-criteria R-IDs are appended with source tags, never renumbered or replaced. The one sanctioned deletion is a `## Parked unknowns` bullet this session resolved — its answer appears in the section that owns it, and a resolved bullet left standing next to its own answer has broken this.
- [ ] Every question asked passes the one test: a wrong guess would build the wrong thing or ship behaviour the user would reject, the code, docs, an experiment, or implementation cannot settle it, and it is the answerer's call. A question walked from a bank topic, a performance or edge-case probe implementation would surface, or a success-metric or latency-budget question on a spec not about them has broken this.
- [ ] Answers are recorded at the precision given: a preference lands in `## Decision Context` as guidance, and a numeric or measurable acceptance criterion appears only when the user stated the number. A recommended option that became a threshold has broken this. Refine writes no placeholder under an empty section.
- [ ] The completion summary reports the question count (zero with "the spec is clear enough to build"), the skip disposition when there were skips, and which sections the session changed.
- [ ] Wildly divergent independent answers to one question (scouts, docs, probes) trigger a reframe-and-re-run of the question. A run that averaged divergent answers, or quietly picked a favorite, has broken this.
- [ ] The next-step suggestion for a spec without tasks names both `/flow-next:plan fn-N` and the `/flow-next:work fn-N --no-plan` alternative for ready cohesive specs. A hint offering only the plan path has broken this.
- [ ] Under `--scope=research`, exactly one of `research: skipped(...)`, `research: rerun(...)`, or `research: running(docs-scout, practice-scout, docs-gap-scout, memory-scout)` is printed before any scout dispatch, the skip is decided from a present `## Resolved via Research` section or plan's findings on the tasks, and a skip writes nothing. A run that dispatched a scout first, asked an interview question, or ran repo-scout, spec-scout, or flow-gap-analyst in this pass has broken this.
- [ ] Every bullet the research pass writes under `## Resolved via Research` ends in a `Source:` link sits under its scout's `###` sub-block, and the section carries its provenance line naming the scouts; every other section comes back byte-for-byte.
