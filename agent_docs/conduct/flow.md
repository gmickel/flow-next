# Conduct checklist - /flow-next:flow

A correct attended run reads whatever it was given, routes from the shared routing reference, runs the routed stage skill, re-evaluates after each hop, and stops at the next human decision with a self-contained report. A correct `--auto` run selects one ready spec, classifies each hop from the same routing reference, dispatches exactly one stage per hop with `mode:autonomous`, verifies from observed state, and ends with one terminal `PILOT_VERDICT` line (one hop under `--tick`).

- [ ] Without `--auto`, under any autonomy marker the run stops with the `NEEDS_HUMAN:` line before any read, route, or dispatch. With `--auto`, only `FLOW_RALPH` / `REVIEW_RECEIPT_PATH` refuse (pilot's exact terminal line); `FLOW_AUTONOMOUS` and `mode:autonomous` do not. A transcript that routed or dispatched under a marker it should have refused, or that refused an `--auto` run on `FLOW_AUTONOMOUS`, has broken this.
- [ ] Every hop names the matrix row it matched, and each row it names exists in `references/route-matrix.md`; a stage skill the run invokes is one that ships. A hop that invented a route, or invoked a retired skill, has broken this.
- [ ] A ready spec with no tasks has its route recorded (`spec set-no-plan` or `spec clear-no-plan`) before any mint, and a plan route names one of the four positive signals from `references/plan-vs-no-plan.md`. A plan route justified by risk, size, or file count has broken this.
- [ ] A bare invocation resolves its item down the Step 1 ladder (last touched in this conversation, current branch, uncaptured intent, next open spec) and routes it as if the id had been given; the ask is reached only when no rung resolves. A run that asked while the conversation had just captured a spec, or that picked one of several plausible open specs without an inline pick, has broken this.
- [ ] At most one blocking question per hop, and only after the fork was classified as a product or preference call; an observable fork shows an experiment or prototype in the transcript instead of a question.
- [ ] Every stage reached carries exactly one `stage: <name> - ran | skipped(<kind>: <detail>) | failed(...)` line in the final report, including a QA skip under `pipeline.qa=auto`. A stage with no line has broken this.
- [ ] The run ends at the PR (run from intent) or when merge is the only step left (open-PR run); the transcript contains no merge, no spec close, and no `/flow-next:land` or second-driver (`/flow-next:flow --auto`, `/flow-next:pilot`) dispatch.
- [ ] An `--explain` run prints the route, signal, skip and skip kind, and the rejected alternatives, and the transcript shows no write under `.flow/` and no stage dispatch.

Rows for `--auto` (the unattended shape; `auto.md` is read only when the token was parsed):

- [ ] The response ends with exactly one `PILOT_VERDICT` line and nothing after it. A long-horizon run names every dispatched stage in order joined by `+` and carries the last hop's verdict; a `--tick` run names one stage (`qa+make-pr` only under `pipeline.chainStages` on). A run that printed prose below the verdict, or two verdict lines, has broken this.
- [ ] Every hop classifies from the routing reference and echoes the row (`route-matrix.md`) and gate section (`gate-selection.md`, `plan-vs-no-plan.md`) it came from; the transcript names no stage table of its own. A hop that invented a route has broken this.
- [ ] Each hop dispatches exactly one stage skill from `{plan, plan-review, work, qa, make-pr}` with `mode:autonomous`, then re-reads state and echoes one `Evidence:` block plus one `stage:` line for it; only an `ADVANCED` hop whose stage is not `make-pr` starts another hop. Merge, land, resolve-pr, capture, refine, and chart never appear as a stage.
- [ ] A zero-task ready spec with no recorded route has the route recorded (`spec set-no-plan` or `spec clear-no-plan`) and the deciding signal echoed (`route: direct - ...` or `route: plan - ...`) before any mint; a recorded route, an intentional plan, an explicit design-review request, or a `needs_work` / `needs_human` plan review is left authoritative.
- [ ] At the all-done hop the QA decision follows `gate-selection.md`: the transcript shows either a `qa` dispatch or the `stage: qa - skipped(config: pipeline.qa=auto: <reason>)` line before make-pr, never neither. In long-horizon mode `pipeline.chainStages=on` produces one stderr notice and no chain; under `--tick` it still chains `qa+make-pr`.
- [ ] The rails hold: the dirty-tree guard runs at start and after every hop (crash-class `NEEDS_HUMAN`, no strike), a healthy no-advance hop records a strike and ends the run (`strike 2/2` unreadies the spec and the reason names `flowctl pilot strikes clear <id>`), the all-done PR probe defers an open PR to land, the run asks the user nothing, and a `--explain` run writes no ledger, records no route, checks out no branch, and dispatches nothing.
