# Conduct checklist - /flow-next:flow

A correct attended run reads whatever it was given, routes from the shared routing reference, runs the routed stage skill, re-evaluates after each hop, and stops at the next human decision with a self-contained report. A correct `--auto` run selects one ready spec, drives it hop by hop with `mode:autonomous`, verifies from observed state, and ends with one terminal `PILOT_VERDICT` line (one hop under `--tick`).

- [ ] Without `--auto`, under any autonomy marker the run stops with the `NEEDS_HUMAN:` line before any read, route, or dispatch. With `--auto`, `FLOW_AUTONOMOUS` and `mode:autonomous` do not refuse, and `auto.md` is read only when that token was parsed. A transcript that routed under a marker it should have refused, or refused an `--auto` run on `FLOW_AUTONOMOUS`, has broken this.
- [ ] Every hop prints one `Route:` line (`Route: <route> (code)` or `Route: <route> (host)`) and the route it takes is a row of `references/route-matrix.md` or `route-matrix-more.md`; references are read only at the step that names them. A stage skill the run invokes is one that ships. A hop that invented a route, or invoked a retired skill, has broken this.
- [ ] A ready spec with no tasks and no recorded route has the route recorded (`spec set-no-plan` or `spec clear-no-plan`) before any stage runs, and a plan route names one of the three positive signals from `plan-vs-no-plan.md`. A plan route justified by risk, size, or file count has broken this. Work is invoked with the branch flow picked (`--branch=current` off the default branch, else `--branch=new`, unless the user named one), stated in one line; work never asks a branch question under flow.
- [ ] A bare invocation resolves its item down the `no-argument.md` ladder (last touched in this conversation, current branch, uncaptured intent, next open spec) and routes it as if the id had been given; the open ask is reached only when no rung resolves. A run that asked while the conversation had just captured a spec, or picked one of several plausible open specs without an inline pick, has broken this.
- [ ] At most one blocking question per hop, and only on a product or preference fork; an observable fork shows an experiment or prototype in the transcript and its `fork-gate:` line instead of a question.
- [ ] Every stop prints the report shape: `Flow stopped at:`, `Route taken:`, one `stage: <name> - ran | skipped(<kind>: <detail>) | failed(...)` line per stage reached (a QA skip included), and `Next:`. Default attended flow stops at the PR; landing runs only with `--until=merge` or current explicit consent (one `AskUserQuestion` offer for an existing open PR), and a decline or no answer dispatches no land. `--explain` prints its `Next:` / `Route:` / `Signal:` / `Skip/narrow:` / `Why not the alternatives:` lines and writes nothing under `.flow/`.

Rows for `--auto`:

- [ ] The response ends with exactly one `PILOT_VERDICT=<ADVANCED|NO_WORK|DEFERRED_TO_LAND|BLOCKED|NEEDS_HUMAN> spec=... stage=... reason="..."` line and nothing after it. A long-horizon run names every dispatched stage in order joined by `+` and carries the last hop's verdict; a `--tick` run names one stage. Prose below the verdict, or two verdict lines, has broken this.
- [ ] Each hop dispatches exactly one stage skill from `{plan, plan-review, work, qa, make-pr, land}` with `mode:autonomous`, uses the route from its `pilot snapshot` (no second judge call), then re-reads state and echoes one `Evidence:` block plus one `stage:` line. A zero-task spec echoes `route: direct - ...` or `route: plan - ...` before any mint. Default continuation stops after `make-pr`; `land` runs only under the merge destination or current scoped consent, at most one land dispatch per hop, bound to the selected spec's PR and never a substitute.
- [ ] At the all-done hop the QA decision follows `gate-selection.md`: the transcript shows either a `qa` dispatch or the `stage: qa - skipped(config: pipeline.qa=auto: <reason>)` line before make-pr, never neither.
- [ ] The rails hold: the dirty-tree guard runs before selection and after every hop (`NEEDS_HUMAN`, no strike); a healthy no-advance build hop records a strike (`strike 2/2` unreadies the spec and names `flowctl pilot strikes clear <id>`); an open PR without landing authority ends `DEFERRED_TO_LAND`, never `NO_WORK`; the run asks the user nothing; and `--explain` writes no ledger, records no route, checks out no branch, and dispatches nothing.
- [ ] Under `--goal`, the final review resolves its backend before it runs (the invocation's `--review`, else `review-backend <goal-id>`); `none` or `ASK` records the skip in the goal log and the final PR body and the run still opens the final PR. A goal run that stopped at the final review for want of a backend has broken this.
- [ ] Discoveries that do not block the goal are listed as follow-ups in the final report, and the final report carries a Decisions list: each default chosen, finding declined, and review skipped, with its evidence. An unattended run that fixed a non-blocking discovery, or ended without the Decisions list, has broken this.
