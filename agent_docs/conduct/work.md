# Conduct checklist — /flow-next:work

A correct run executes a spec or task end to end — branch setup, fresh-context workers per task, review, quality gates, and a final summary — with all task state read and written through `flowctl`.

- [ ] Task state moves only through `flowctl start` and `flowctl done`, and each completion is confirmed by `flowctl show <task-id> --json` reporting `done` before completion is claimed. A session that tracks tasks with TodoWrite or a markdown plan file outside `.flow/` has broken this.
- [ ] The branch question is answered before any file is read or code written; under autonomy the run defaults to a new branch named exactly the spec's `branch_name` field rather than an ad-hoc name.
- [ ] Phase 3 prints exactly one `Scheduling:` line before any claim - `rolling` by default, `wave (<reason>)` only for a task-id run, plan-sync on, fewer than two open tasks, or a sequential dependency chain, or the scheduler's own `degraded to wave (host lacks non-blocking dispatch)` after a measured probe. A run with no line, a rolling run under `planSync.enabled=true`, or a route picked from a host name, a config knob, or a Touches comparison has broken this.
- [ ] On the rolling route every admission event prints the report block - the wave-route lines plus `In-flight:`, `Admitted:`, and `Held:` (each held task with its reason) - and admission is recomputed after each event (worker return or review completion), never precomputed for the run. Every dispatched worker, including a one-task admission, carries `PARALLEL_WAVE: true` and returns the parallel handover; the conductor integrates that task, runs its review itself, and calls `flowctl done` only on SHIP. A worker that self-completed, or a join conflict resolved by hand instead of one serial retry, has broken this.
- [ ] On the rolling route the notes directory is created at Phase 3 start under the state-dir sibling, keyed by spec id + run identifier; its path (never its content) rides every worker and scout dispatch prompt; it is deleted only after Phase 5 completes cleanly. A creation failure degrades to `Notes surface: unavailable (...)` and the run continues. Cross-run claim contention fails closed: the loser drops the task rather than clearing the claim; a run that used `--force`/`--reclaim` to take another run's task has broken this.
- [ ] Each task is implemented by a fresh-context worker subagent, and on the wave route the frontier decision is reported before claiming (`Ready frontier`, `Selected wave`, `Selection rule`, `Isolation`, `Dispatch count`, and a sequential-fallback reason when one applies). A wave dispatched with a missing or overlapping `**Touches:**` declaration, or claimed without a stated `Selection rule:`, has broken this.
- [ ] A concurrent wave commits the spec and task files before its workspaces are created, and each completed task's evidence names the INTEGRATED commit SHAs rather than the worker's workspace-branch SHAs. A `flowctl validate` warning that an evidence commit "is not reachable from HEAD" on a task the wave just finished has broken the second half; a worker reporting it cannot find its task has broken the first.
- [ ] When the resolved review mode is `host-deferred`, the conductor runs `/flow-next:impl-review` itself against the task's re-read base and only calls `flowctl done` after a SHIP verdict, with review-fix commits and the receipt appended to that task's evidence.
- [ ] Each worker return is pointer-shaped — task id, terminal status, summary/evidence paths, commit range, workspace and gate results on a parallel-wave task, and the review verdict where the path allows it. A return that restates the summary content the files already carry has broken this.
- [ ] Every stage the run reached records one stage-outcome line in the receipt surface it already writes — plan-sync included, whether it ran, skipped with a reason, or failed. A stage with no line reads as failed.
- [ ] The run closes with the mandatory final summary block, including a `Tracker sync:` slot in one of its four states (`n/a (bridge inactive)` when no tracker is configured), one `Gates:` line per accumulated Phase 4 outcome, and the executable `Next:` handoff line.
- [ ] When the Phase 4 quality audit fires, both axes are dispatched in a single message — one `AXIS: correctness` and one `AXIS: standards` call to the same auditor agent. A transcript that sent one axis, read its report, and only then sent the other has broken this.
- [ ] Both axis reports are surfaced verbatim under `### Correctness axis` and `### Standards axis`, followed by one count-plus-worst-tier line per axis. A merged, reranked, or interleaved findings list, or an axis dropped because the other looked worse, has broken this.
- [ ] No Critical finding is attributed to the standards axis — its charter ceiling is Should Fix, so a standards-axis Critical is reported as a charter break rather than actioned as a blocker.
- [ ] An explicit `--review=export` request is refused at option-parse time, before any dispatch, with a message naming `/flow-next:plan-review --review=export` as the manual path. A run that passed `export` through as `REVIEW_MODE` or escalated it mid-dispatch has broken this.
- [ ] The 3g policy skip persists `completion_review_status=not_required` through the compare-and-set setter (`--status not_required --if-current unknown`, branching on `written`); a CAS miss falls through to the normal status check. Work never writes a verdict status (`ship`/`needs_work`/`needs_human`) — a skip that wrote `ship`, or that read-then-wrote without the CAS, has broken this.
- [ ] Every dispatch prompt carries the `FORBIDDEN` line (the task's declared Touches echoed, worker lifecycle writes exempt, no force-push or rebase of the target) and a conductor-set `TIMEBOX` with the return-partial contract, and lane progress is judged by side effects only — commits, a moved task status, handover files. A past-timebox lane with none is stood down, the stand-down counting against the existing 2-strike cap, never a third budget; a lane judged healthy on its narration alone has broken this.
- [ ] A re-anchoring continuation worker treats the inherited trail as authoritative for what was decided and written but re-verifies every inherited pass/fail claim on the real artifact before `flowctl done`, and a pause happens only at a wave boundary on an explicit pause request or imminent-compaction signal, writing the workspace/handover resume map to `/tmp/<spec-id>-resume.md`. A continuation that trusted an inherited "tests green", or a self-granted mid-wave pause, has broken this.
- [ ] Workspace teardown waits for BOTH conditions — the task's commits reachable from the target HEAD and a clean workspace tree — with uncommitted work pausing cleanup and reported, never deleted; a caught test/gate/baseline manipulation is hardened in its own change, never merely reverted; and the final summary counts an all-done spec with no PR as zero shipped, its `Next:` line naming the remaining work. A deleted dirty workspace, a bare revert of a caught gate edit, or a victory-lap summary over an unmerged branch has broken this.
- [ ] A zero-task spec-id start fires the explicit fork: interactive runs ask plan-first vs work-directly with an agent-judged recommendation and its reason, a `--no-plan` flag, natural-language intent, or the spec's own `no_plan: true` field (fn-214) pre-answers so the ask never fires, autonomous runs without that explicit instruction stop with the typed "spec has no tasks" report, and the direct route mints exactly one minimal implicit task (`satisfies` all spec R-IDs, no `Touches:` line) before the standard pipeline. A silent zero-task fall-through, an ask under autonomy, or a second mint has broken this.
