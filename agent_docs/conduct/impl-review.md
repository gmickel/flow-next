# Conduct checklist — /flow-next:impl-review

A correct run coordinates a review of the branch's implementation through exactly one configured backend, reports the verdict flowctl computed, and on `NEEDS_WORK` makes one fix pass followed by one re-review.

- [ ] The backend is resolved once in the setup block — a single `flowctl review-backend` call, or a `--review=<backend>` flag that skips it. On the codex default path no backend workflow file is read; any other backend, `--deep`, `--validate`, `--interactive`, `--no-triage`, or an instruction about reviewer topology reads `other-paths.md` and then only the matching `workflow-<backend>.md`. `ASK` stops, `none` says so, a removed `rp` or `export` value prints the removal notice and stops like `ASK`. A transcript that loads two backend workflow files has broken this.
- [ ] On codex, a small diff in one area that touches no persisted or shared state, concurrency, security or data layout runs one draw (`--draw correctness`); anything else runs the default three. A qualifying trivial diff (lockfile, docs, release, generated files) ends at the `triage-skip` SHIP with no draw.
- [ ] The coordinator never authors the verdict: it writes a merge plan (collapse same-defect findings onto the strongest; leave out findings with no concrete failing scenario in the change) and `impl-review-fanout-finalize` computes the verdict and writes the receipt. A reported verdict that differs from flowctl's output, or a SHIP with no backend response behind it, has broken this.
- [ ] `NEEDS_WORK` gets one fix pass: only findings showing the change itself does the wrong thing in a scenario the request covers are fixed, with focused tests and a commit of only the changed files; the rest are listed as follow-ups as plain facts, with no question about which to fix and no offer to fold them in. Then exactly one re-review (`codex impl-review`, resuming the reviewer's session), whose verdict is terminal when attended. Unattended (or when asked to review until SHIP), fix and re-review repeat until SHIP, each declined finding gets a `Declined #<n>: <reason>` line in the fix commit, and the author may end the loop with an `OVERRIDDEN:` line only when every remaining finding is hardening, scope creep or pre-existing and below Major. An attended second fix pass, an override over a broken stated requirement, or a question to the person about which findings to fix has broken this.
- [ ] `MAJOR_RETHINK` stops with `BLOCKED: DESIGN_CONFLICT` and the reviewer's rationale instead of being patched finding by finding; `NEEDS_HUMAN` hands the reviewer's question to the person.
- [ ] Every review command runs as one blocking foreground call with a 600-second timeout, never backgrounded. A transport error with no verdict is retried once; `ESCALATE:`, `TRANSPORT_UNHEALTHY`, `NOT_RETRYABLE:` and other refusals end the review with the message as printed. A delivered verdict reframed as a transport failure, a widened reviewer sandbox, a direct `codex` call, or a review-state reset has broken this.
