# fn-159 Convergence-aware review terminals and per-surface blocking calibration

## Goal & Context
<!-- scope: business -->

The deterministic review cap (fn-90/fn-131) counts dispatches, and a dispatch counter cannot distinguish a genuinely stuck review loop from one converging in severity while each fix surfaces one more small finding. Field evidence, 2026-08-02 session (flow-next repo): three plan reviews hit the cap at 4 with only trivial residue left — fn-155 (findings 8→7→3→3, then human reset → SHIP on the next round, having burned 4 rounds at an identical head SHA), fn-153 (severity P0→P1→P2, reset → SHIP), fn-156 (4 findings → 1 stale-prose finding, capped). Meanwhile flow-swarm shows the opposite tail: fn-147 hit the cap on 3 of 4 tasks, round 3's fix introduced a fresh P0, and when the budget ran out six findings were applied by the conductor and shipped **with no re-review** (`SHIP_WITH_CONDUCTOR_FIXES`) — cap exhaustion produced an unreviewed ship, which is worse than an early escalation.

The interim mitigation (already in tree, uncommitted): `MAX_REVIEW_ITERATIONS` default raised 4→8. The docstring names this spec's work as the real fix: a convergence-aware terminal built from the structured findings the system already persists (fn-136), plus an explicit escalate-to-human path, plus per-surface blocking calibration so trivial plan-prose residue stops consuming rounds at all.

The system already produces the convergence signal on every round — per-finding severity, confidence, classification (introduced/pre_existing), status (fixed/not_fixed/withdrawn), and cross-round lineage via `priorFindingId`/`supersedesReceiptId`, schema-validated in receipts — and then ignores it: the cap logic never reads it, and the ratchet's memory is a raw prose blob truncated at 8000 chars.

Second calibration problem: one severity vocabulary and blocking contract is applied to three surfaces doing different jobs. Plan review blocks on prose self-consistency that cannot cause a bad downstream outcome; impl review can re-litigate settled plan decisions; the land-loop PR bot (a black box we cannot re-prompt) gets zero scope guidance in its trigger comment and its prose findings can gate a merge that impl review already passed.

## Architecture & Data Models
<!-- scope: technical -->

All flowctl changes are zero-judgment plumbing (hash comparison, JSON walks over already-validated receipt data, fixed threshold rules) — consistent with the "flowctl grows only under burden of proof" principle. No new LLM calls anywhere. Every new mechanism can only END a loop earlier (early escalate, forced terminal); nothing can grant, refund, or extend rounds.

**Components touched:**

1. **Dispatch guard (flowctl)** — in `enforce_and_increment_review_cap()` (flowctl.py:9429; new code after the sidecar-exists check ~:9460, before the cap branch): before reserving a round, compare a content hash of the reviewed artifact against the baseline (below). **Hashes are domain-separated by review type** (review-round-1 P0): plan = spec markdown + all child task markdown (sorted, normalized); impl = the dispatched diff content; **completion = spec + tasks + the dispatched diff + applicable global-criteria content** (`.flow/criteria.md`) — a completion `NEEDS_WORK` fixed by an implementation-only change MUST re-dispatch cleanly, and plan-vs-completion must never equate despite sharing a counter (the hash key includes the review type). Reuse `_file_sha256` (:10388) / the normalized-blob hash pattern. Unchanged hash → refuse with `NOT_RETRYABLE: artifact unchanged since last verdict` under the generic error path (exit 1), consuming nothing. `--force` dispatches and consumes normally. **Hash-compute failure fails OPEN** (dispatch proceeds with a logged warning) — the guard is a waste-saver, never a review-blocker.
   **Baseline + reset via hash epoch** (review-round-1 P1: `review_attempts` is append-only, so "clear the baseline" cannot mean deleting rows): spec state gains a per-counter-scope `review_hash_epoch` integer; every attempt row is stamped with the epoch current at reservation; the baseline is the latest consumed verdict row **in the current epoch**. ALL counter-reset paths — `cmd_spec_reset_review_rounds`, `review-rounds reset`, AND the in-process SHIP reset inside `record_review_attempt`/`reset_review_cap` — advance the epoch, each preserving its existing pending-reservation semantics (explicit re-plan pops matching pending keys; `reset_review_cap` never touches them, fn-134.7/R22). This preserves the fn-155 recovery path (reset → re-review without an edit) without `--force`.
   **Reservation provenance** (review-round-1 P1: RP reserves and finalizes in separate processes; a count can't carry per-reservation state, and FIFO would corrupt on out-of-order finalize): `review-rounds increment` returns a **reservation id**; flowctl persists reservation metadata `{artifact_sha256, forced, epoch, review_type}` keyed by that id alongside the pending count; `review-rounds record` (and the in-process finalizers) accept the id and consume the metadata onto the attempt row at finalize — refund arithmetic unchanged. **The caller supplies the artifact identity** (review-round-2 P1: re-reading repo files inside the reserve helper would not hash what the reviewer actually receives): reserve inputs are an explicit `--review-type` and a caller-computed `--artifact-sha256` (or `--artifact-file` for flowctl to hash) of the FINAL dispatched artifact — after Cursor prompt fitting, after RP prompt assembly; in-process handlers compute it post-assembly and thread it internally. Missing artifact hash → guard inert for that round (compat), never a refusal. **Unknown or missing reservation id at record time is REJECTED with exit 2 and zero mutation** (review-round-2 P1: silently decrementing an unidentifiable pending count strands metadata and breaks the rightful finalizer); an id-less compatibility path is permitted ONLY when no metadata map exists and exactly one legacy reservation is pending. Every finalized attempt row is stamped with its `reservation_id` (review-round-3 P1: metadata is consumed at record, so later consumers need a durable attempt identifier). **Reserve point and artifact blob are defined per transport** (review-round-3 P1): a deterministic artifact-blob builder per review type (plan = sorted normalized spec+task md concatenation; impl = the exact diff text handed to the reviewer; completion = spec+tasks+diff+criteria concatenation) produces the `--artifact-file` input; RP resolves its mode FIRST via a side-effect-free probe (review-round-4 P1: `rp setup-review --create` both determines RP_MODE and, on CE, performs the review — too late to pick a reserve point): a new deterministic `rp mode-probe` (CLI-availability based, no window/tab mutation) lets the workflow branch BEFORE any reservation — CE reserves immediately before the setup/review call; Classic reserves after final prompt assembly immediately before `chat-send`; each branch creates exactly one reservation and a setup failure refunds only reservations actually made (tested per branch); Cursor hashes the post-fit whole prompt's diff component (the blob the reviewer actually receives); host reserves in its dispatch fence after the reviewer subagent's input is composed. Tests bind the stored hash to the exact post-fit artifact content supplied to the reviewer. Tests: unknown, duplicate, concurrent, out-of-order finalization; intervening-file-change; Cursor-fitted-diff hashing. The plan/impl/completion **workflow-rp.md AND workflow-host.md files are in scope** to pass the id between their reserve and record fences, with at least one host-path reserve/finalize regression.
   **Cross-process locking** (review-round-3 P1: reserve/finalize/refund/reset/backfill are read-modify-write cycles over one spec JSON; atomic replace alone loses concurrent updates): one sidecar-scoped cross-process lock (flock under `.flow/locks/`, the existing lock home) wraps EVERY state transition — reserve, finalize/refund, SHIP reset, explicit reset, digest backfill — leaving refund arithmetic and pending semantics unchanged; tests exercise truly overlapping processes, not just sequential outstanding reservations. **Lock-order contract** (review-round-4 P1: receipt writes already take a receipt-path lock; two-resource ops could deadlock or race lineage): for any operation touching both, acquire RECEIPT lock BEFORE SIDECAR lock, holding both from lineage validation through sidecar mutation and receipt publication; overlapping RP-attach vs in-process-finalize tests, including stale-lineage and write-failure recovery.
   **Delivered-verdict persistence recovery** (review-round-4 P1; hardened rounds 5-6): before a reservation is consumed, flowctl writes a durable per-reservation **finalization journal** under `.flow/review-runs/` (NOT /tmp) — a complete write-ahead operation: extracted response text + checksum, the exact intended receipt payload (session/model/effort, resolved backend spec, focus/base metadata, parsed tallies, timestamp) and the validated findings container with its prior-lineage identity, receipt target path, review scope/type, reviewed SHAs, verdict, and status target — cleared only after every applicable write completes. **The journal is complete BEFORE the reservation is consumed on every path** (round-7 P1: RP previously built the container only at attach, after record): `review-rounds record` itself constructs and journals the exact receipt operation and validated findings container from its inputs (response file plus receipt/status-target parameters it gains for this purpose) before consuming the reservation; `review-findings attach` then publishes/backfills FROM the journal rather than re-deriving. A fresh-process crash immediately after record but before the attach fence creates its input file is a named test. **Journals are themselves authoritative recovery work** (round-6 P1: a crash after journal write but before attempt creation would otherwise evade an attempts-only gate): the pre-increment gate scans in-scope journals and reconciles each against reservation metadata and attempt rows — an unconsumed journal resumes the original finalization, never permits a new dispatch. Byte-equivalent receipt replay is tested after process restart and after the receipt pointer has advanced; the journal-written/attempt-not-created boundary is a named test. Attempt rows carry finalization progress with three-valued states `finalized: {receipt, digest, status}` each `pending | complete | not_applicable` (`not_applicable` set at creation for surfaces that lack that leg — e.g. standalone reviews with no status — so inapplicable legs never block recovery). **Idempotent replay:** every receipt/finalization write carries the reservation identity; replay recognizes an exact-match already-applied write as a successful no-op — crash boundaries (receipt-published/progress-unmarked; digest-written/receipt-missing) are each defined and tested in a fresh process with the original /tmp response file deleted. **Any-incomplete gate** (round-5: latest-row checks miss concurrent stragglers): a new reservation is refused while ANY consumed-verdict attempt in scope has a `pending` leg — those are replayed deterministically first, zero dispatch; status-write surfaces gain `--reservation-id` and require exactly one matching attempt. **Typed recovery result — plural** (rounds 7-8: multiple incomplete journals can coexist under the concurrency model): a replay returns exit 0 with JSON `{replayed: true, replays: [{reservation_id, verdict}, ...]}` and NO reservation created; NO dispatch until every in-scope journal is complete; callers apply deterministic terminal precedence NEEDS_HUMAN > NEEDS_WORK > all-SHIP (SHIP only when every replay shipped); per-verdict and mixed-verdict (two incomplete journals) tests prove zero dispatch. **`finalized.digest` tracks the digest OPERATION, not digest presence** (round-7 P1: absent/legacy/malformed findings are a SUCCESSFUL parse outcome): a completed validated parse that yields no supportable digest marks the leg `complete`; only an interrupted or failed operation stays `pending` — malformed, legacy, and no-findings recovery tests confirm the gate never blocks on legitimately absent findings. Tests: A-incomplete/B-complete ordering, out-of-order status completion, induced attach/backfill/status failures for SHIP (and for NEEDS_HUMAN once .3 lands).
   **SHIP reset is system-owned** (review-round-2 P0: the RP workflows currently run `review-rounds reset` after SHIP, which R9's Ralph guard would block, breaking autonomous SHIP): `review-rounds record` atomically resets the counter AND advances the hash epoch when recording a SHIP verdict (extending the existing folded reset path, preserving the pending-reservation invariant); the explicit `review-rounds reset` commands are REMOVED from all three workflow-rp.md Phase-4/receipt sections. The direct reset verbs remain as human-only recovery tools — and only because no autonomous path needs them anymore can they be guard-blocked cleanly.
2. **Stall detector (flowctl)** — same call site, after the hash guard. **Input is NOT a receipt walk** (review-round-1 P1: `enforce_and_increment_review_cap` has no receipt path, `load_review_receipt_generations` scopes by (type,id,mode) so backend/type switches restart lineage, and `/tmp` receipts are ephemeral): the detector reads compact **findings digests** persisted on attempt rows, from spec state only — durable and counter-scoped by construction.
   **One authoritative digest construction point** (review-round-2 P1: in-process handlers finalize the attempt BEFORE the receipt is written, and RP records BEFORE `review-findings attach`, so record cannot "reuse" a container that doesn't exist yet): the digest derives from the SAME `build_review_receipt_findings` container the receipt gets. In-process paths build the container first and pass digest + container into finalize/receipt-write together; the RP path has `review-findings attach` (which gains `--reservation-id`) **backfill the digest onto the attempt row stamped with that reservation id** after it validates the container — backfill requires exactly one matching consumed-verdict row with matching scope, backend, and reviewKind; unknown, duplicate, transport-failure, or already-conflicting attachments fail with zero mutation. A test asserts receipt findings and attempt digest derive from one container.
   **Digest shape with provenance** (review-round-2 P1: `classification: introduced` describes relation to the reviewed change, NOT round-level newness): ≤40 items × {findingId, chainRoot (derived across `priorFindingId`/supersession hops at container build), severity, status, classification, **firstSeenThisRound** (true iff no prior-round chain link)}, plus digest-level `backend` and `reviewKind`; >40 items sets `digest_truncated: true` (inert round).
   Rules — evaluated over the last 2 consecutive consumed verdict rounds in the same counter scope and current hash epoch, both carrying non-truncated digests (absent/legacy/malformed containers → no digest → inert; never a false stall). **Identity-dependent rules (a, c) additionally require both digests to share backend AND reviewKind** — an unlinked backend/type transition breaks chain identity, so they go inert across it; the aggregate rule (b) needs no identity and stays live:
   - **(a) Persistent not-fixed:** the same chainRoot carries `status: not_fixed` in both rounds.
   - **(b) Flat trajectory:** worst open severity did not strictly improve AND open-finding count did not strictly decrease. **Exact math** (`_FINDINGS_SEVERITY_ORDER` maps P0→0 … P3→3, so a naive numeric `max()` inverts): worst = MIN numeric rank over open items (status `open`/`not_fixed`); severity strictly improves iff current worst rank > prior worst rank; an **empty open set = converged — the rule can never fire**.
   - **(c) Regressing fixes:** a finding with `firstSeenThisRound && classification == introduced` at rank ≤ 1 appears in each of the 2 rounds.
   On fire: exit `REVIEW_CAP_EXIT_CODE` (4) with the existing `ESCALATE:` marker plus a stall sub-reason. A `--force`d round is a normal detector input. Rounds finalized without a digest break consecutiveness (inert) — behavior identical to today. Tests: three-round newness, carried introduced findings, multi-hop supersession, backend switch inertness.
3. **NEEDS_HUMAN verdict** — added to the verdict grammar as a fourth terminal (`SHIP | NEEDS_WORK | MAJOR_RETHINK | NEEDS_HUMAN`; completion review gains it as a third: `SHIP | NEEDS_WORK | NEEDS_HUMAN`). Parsed by the existing last-`<verdict>`-tag rule (parse regex :4516 — the sanctioned edge; no new parse surface). **Terminal ordering is persist-THEN-exit** (review-round-1 P1: exiting 4 inside `_finish_backend_exec` or the RP recorder would skip receipt/status persistence): a delivered NEEDS_HUMAN flows through the normal verdict return path — `_finish_backend_exec` returns it like any verdict, `review-rounds record` consumes the round and returns it with exit 0, receipts/`review-findings attach`/status writes all complete — and only the OUTERMOST layer (the backend handler's post-persistence tail for in-process backends; the workflow fence's final step for RP) prints `ESCALATE: reviewer requested human review` and exits 4. Defined per path: plan, impl, completion, standalone, host, and the RP workflow files. It **writes status `needs_human` in BOTH duplicated status maps** (:9388-9392 and :35838), and the status CLI surface (`spec set-plan-review-status` / completion equivalents) extends its argparse choices to accept `needs_human`. **Four code sites for the grammar, not two:** the flowctl maps plus `scripts/hooks/ralph-guard.py` `VALID_RECEIPT_VERDICTS` (L112) and its three `<verdict>(...)` regexes (~L917/932/994) — missing the guard sites makes Ralph reject a legitimate NEEDS_HUMAN receipt. Grammar text updates sweep the four prompt templates + byte-parity fallbacks, skill prose (canonical + codex mirror via sync), ralph-init templates (`ralph.sh`, `prompt_{plan,work,completion}.md`), and GLOSSARY/docs. Tests assert attempts, receipt, and status are all present BEFORE the exit-4 is observed, including a nonzero-exit transport process that still delivered the verdict. Standalone (no-sidecar) reviews parse it too; with no driver watching, the exit-4 marker is the interactive user's signal — fine. Prompt guidance (all surfaces): emit NEEDS_HUMAN when the remaining disagreement is a design judgment call — never as a soft NEEDS_WORK.
4. **Ratchet reads structured findings** — `build_convergence_ratchet_block()` (:9598) consumes `findings.items` from the prior receipt (via a structured sibling of `_read_prior_findings` :9547) and renders a compact numbered list (ordinal, severity, classification, status, title, file:line); the item-by-item accounting contract applies to rendered items. **Cursor fitting is budget-aware, not item-count-capped** (review-round-2 P1: the final Cursor fitter runs AFTER the ratchet joins the rest of the prompt, so a fixed item count cannot guarantee intact items): the ratchet render for the cursor path takes a character budget derived from the actual remaining capacity and appends only whole rendered items while the next complete item plus the closing delimiter still fit; tests cover maximum-length titles/paths and a nearly exhausted prompt, asserting every item boundary and the closing delimiter survive. Prose-blob path retained as a labeled legacy fallback. Injection-neutralization (:9621-9626) and data-not-instructions guards keep current semantics. Applies to all backends incl. host — the host workflow call sites (workflow-host.md per surface) are inventoried in the tasks with a host-path structured-ratchet regression, not assumed covered by `cmd_backend_review`.
5. **Per-surface calibration (prompt templates + fallbacks; hash-pinned)** —
   - **Plan review** (`references/plan-review-prompt.md`, severity line L65): outcome-anchored severity definitions (P0 = following the plan produces a wrong or impossible implementation; P1 = material ambiguity likely to mislead a competent implementer; P2/P3 = consistency/polish — never blocking). ## API Contracts

- Unchanged-artifact refusal: exit 1 (generic error path) with the literal marker `NOT_RETRYABLE: artifact unchanged since last verdict`; no reservation made, no ledger row written. **Driver terminal contract** (round-5 P1: exit 1 alone reads as a generic failure and gets retried): the terminal-owning files per surface — plan-review `workflow.md`; impl-review `workflow-common.md` plus its SKILL.md fix-loop owner; completion-review `workflow-common.md` plus its SKILL.md terminal owner — plus pilot and land workflow prose and the Ralph driver docs/`ralph.sh` (non-pinned; pinned ralph-init prompt templates coordinate via task .4), map exit 1 + this exact marker to a human-action terminal (edit the artifact, human reset, or human `--force`) — never a transport refund, never a redispatch; an end-to-end driver-facing no-repeat regression (Ralph/pilot-shaped, alongside the guard tests) proves the marker terminates without refund, force, reset, or redispatch — these files are inventoried in task .7. `--force` flag on the increment/dispatch surface overrides (human-only by guard policy).
- `review-rounds increment` returns a **reservation id** in its JSON; flowctl persists reservation metadata keyed by that id — exact shape everywhere: `{artifact_sha256: string|null, forced: bool, epoch: int, review_type: string}` (canonical spelling `review_type`; `artifact_sha256` null when the caller supplied no hash) — alongside, not replacing, the `review_pending_rounds` count; `review-rounds record` accepts `--reservation-id` and consumes the metadata onto the attempt row on verdict or refund — refund arithmetic unchanged; out-of-order finalization safe by construction (keyed, not FIFO). Id semantics, precisely: an UNKNOWN supplied id always fails exit 2 with zero mutation; an OMITTED id succeeds only when exactly one reservation is pending in the requested scope (its metadata consumed implicitly) and otherwise fails exit 2 with zero mutation — tests for zero, one, and multiple pending reservations.
- `review_attempts` row: additive optional `artifact_sha256` (string), `forced` (bool, present only when true), `hash_epoch` (int), `reservation_id` (string), `finalized` ({receipt, digest, status} each `pending | complete | not_applicable`; `not_applicable` assigned at creation for legs the surface lacks), and `findings_digest` — exact shape: `{backend: string, reviewKind: string, digest_truncated: bool, items: [{findingId, chainRoot, severity, status, classification, firstSeenThisRound}]}` (≤40 items; `chainRoot` is the canonical chain identity everywhere — `chainId` does not exist; every provenance field validated at write). No schema break; existing readers ignore them.
- Spec state: additive `review_hash_epoch` map, exact shape `{"plan": int, "impl:<canonical-task-id>": int}` (keys mirror the counter scopes; absent key reads as 0); ALL reset paths advance the matching scope(s) — `spec reset-review-rounds --impl` advances EVERY `impl:*` epoch it wipes.
- Verdict grammar: `NEEDS_HUMAN` accepted on all backends + host; status maps and the status CLI argparse choices accept `needs_human`; receipts record the verdict verbatim. Exit codes 2/3/4/5 unchanged in meaning; 4 gains two marker variants (`ESCALATE: review loop stalled (<rule>)`, `ESCALATE: reviewer requested human review`) alongside the cap marker, emitted only AFTER all persistence completes.
- No `.flow/config.json` key additions or renames (no schema regen needed).

## Edge Cases & Constraints

- **Hard constraints preserved (load-bearing, from fn-90/fn-131 history):** (1) the implementing agent can never reset or extend its own gate — all new mechanisms are shorten-only; reset verbs AND `--force` are guard-blocked; (2) a delivered verdict is never re-framed as a transport failure; (3) the cap can never be disabled or set to zero; (4) every round is a real dispatch with real cost — the stall detector claws back the doubled worst case of the 4→8 raise; (5) exit codes 2/3/4/5 keep their meanings for autonomous drivers.
- **Runaway proof:** worst case remains exactly `MAX_REVIEW_ITERATIONS` real dispatches. Detector and NEEDS_HUMAN only terminate earlier. Transport refunds (fn-131) unchanged; `reset_review_cap` still never touches `review_pending_rounds` (fn-134.7/R22 invariant).
- **Reviewer gaming:** the reviewer could skew severities/statuses to keep rounds alive, but it has no self-grant path — it emits data; flowctl applies fixed rules; extension is bounded by the hard cap regardless. Cross-model, auditable in receipts.
- **Detector false positives:** rules require 2 consecutive qualifying verdict rounds; early escalation on a loop that would have self-resolved at round 5 is acceptable (human sees converged-except-residue and resets). Fail-inert everywhere: legacy/absent/malformed findings, lost lineage, or a hash-compute failure never produce a false stall or a blocked review.
- **NEEDS_HUMAN vs MAJOR_RETHINK:** MAJOR_RETHINK stays "the approach is wrong — redesign"; NEEDS_HUMAN is "a human must adjudicate." Prompts state the distinction so NEEDS_HUMAN doesn't cannibalize either verdict.
- **Prompt-text discipline:** every prompt change updates the SHA-256 pins in `test_prompt_text_pinned.py` in the same commit with rationale; the four extracted-prompt `*_FALLBACK` constants stay byte-identical to templates (`test_review_prompt_template_parity`); `VALIDATOR_TEMPLATE_FALLBACK`/`DEEP_PASSES_FALLBACK` are deliberate condensations — never sync. **Beyond pins** (review-round-1 P1): the parity suite also enforces rendered-prompt invariants — text outside `## Output Format` stable, no size growth, masked-hash fixtures. The calibration and grammar edits WILL violate those as written; the tasks explicitly include a deliberate rebaseline of the rendered fixtures and size contract with rationale + before/after token counts (or trimming obsolete text to fit) — never a blind fixture update. **The parity suite also binds a token-measurement evidence artifact** (review-round-4 P1: `test_actual_token_measurement_is_bound_to_assembled_prompts` reads `optimization/reached-path/evidence/fn136/review-output-format-token-delta.json` and asserts candidate hashes + measured deltas against every assembled prompt): task .4's scope includes regenerating or superseding that artifact with an fn-159 evidence file — candidate hashes, baseline binding, tokenizer counts, and acceptance flags regenerated by the documented procedure, not hand-edited.
- **Cross-platform:** `./scripts/sync-codex.sh` twice (idempotency); canonical prose stays portable; flowctl propagation to `.flow/bin/` + tracker manifest + parity tests per CLAUDE.md final-gate rules. Guard hooks don't fire on Cursor (different hook events) — the reset/force block degrades to prose-only there, as all guard rules already do.
- **Open-spec coordination:** fn-142 (maintainability block, same plan-review prompt) and fn-149 (same land docs) land AFTER fn-159 or rebase onto it — fn-159 owns the severity/contract rewrite; fn-142's block composes on top. fn-120 (flowctl.py Windows sweep) must not run concurrently with fn-159's flowctl edits.
- **No-sidecar reviews stay uncapped** (existing early-return :9460-9462); guard/detector inert without a sidecar.

## Acceptance Criteria
<!-- scope: both -->

- **R1:** flowctl refuses to dispatch a re-review when the caller-supplied domain-separated artifact hash (plan: spec md + all child task md; impl: the FINAL dispatched diff; completion: spec + tasks + dispatched diff + global-criteria content; hash key includes review type; computed AFTER Cursor fitting / RP assembly, passed to the reserve seam via `--review-type` + `--artifact-sha256`/`--artifact-file`) equals the baseline — the last consumed verdict row in the same counter scope AND current `review_hash_epoch`. The refusal consumes no round and prints `NOT_RETRYABLE: artifact unchanged since last verdict` (exit 1). `--force` overrides, consuming normally and stamping `forced: true`. Hash-compute failure or absent hash fails open with a warning. ALL reset paths advance the epoch — including the system-owned SHIP reset inside `record` — invalidating the baseline without mutating the append-only ledger (fn-155 recovery: reset → re-review with no edit dispatches WITHOUT `--force`; regression tests: completion-after-impl-only-fix, plan→completion never colliding, intervening-file-change, Cursor-fitted-diff). Reservation metadata `{artifact_sha256, forced, epoch, review_type}` travels by reservation id from increment to record; finalized attempt rows are stamped `reservation_id`; unknown id at record is rejected exit 2 with zero mutation; a MISSING id is accepted ONLY when exactly one reservation is pending in scope (ownership unambiguous — its metadata is consumed implicitly), error otherwise — this keeps un-migrated serial RP fences working during the .1→.7 window without weakening out-of-order ownership (round-6 P1); .1 and .7 land as one indivisible unit on the spec branch regardless (no repo state between them reaches main). A sidecar-scoped cross-process lock wraps reserve/finalize/refund/reset/backfill (overlapping-process tests). Reserve points and artifact blobs are defined per transport (Classic pre-chat-send, CE pre-setup-call, Cursor post-fit, host post-compose) via deterministic per-type blob builders; the stored hash binds to the exact artifact the reviewer received. The RP and host workflow files pass the id.
- **R2:** flowctl exits 4 with `ESCALATE: review loop stalled (<rule>)` when the last 2 consecutive consumed verdict rounds in the same counter scope and epoch (read from spec-state findings digests) both carry non-truncated digests and any of: (a) the same chainRoot stays `not_fixed`; (b) worst open severity fails to strictly improve (worst = MIN numeric rank; improvement = current worst rank > prior rank; empty open set = converged, never stall) AND open count fails to strictly decrease; (c) a `firstSeenThisRound && introduced` finding at rank ≤1 appears in each round. ## Boundaries
<!-- scope: business -->

- **Do NOT shrink or demote impl review.** flow-swarm evidence: impl review produced P0s on 6 of 9 receipted tasks and catches fix-induced regressions across rounds; the PR bot found zero issues on fully impl-reviewed PRs. Complementary surfaces; only blocking calibration changes.
- **No reviewer-decides-budget designs.** The reviewer emits data and terminal verdicts only; round arithmetic stays in flowctl. No "should this get another round?" question to any model.
- **No new LLM calls, no new subprocess judges.** Guard and detector are pure plumbing.
- **No new exit codes; no changes to 2/3/4/5 semantics.** Drivers must not need logic changes.
- **Completion review keeps sharing the plan counter.** Split is unproven need — out of scope.
- **No-sidecar (standalone) reviews stay uncapped** — separate concern.
- **No flow-swarm repo changes.** The land-bypass/manual-merge hygiene there is operator follow-up.
- **No per-surface rubric rewrites.** The 8 numbered criteria per surface already diverge fully; only severity definitions, gates, and blocking contracts change.
- **The cap stays count-based and enabled.** No trajectory rule may raise, refund, or disable it.
- **No changes to fn-131 transport-refund machinery** or the `review_pending_rounds` reset invariant.

## Strategy Alignment

Active tracks served by this plan:
- **Ralph autonomous mode** — hardens the loop suite's quality-discipline invariant: reviews now stop on measured non-convergence or reviewer escalation instead of only on a burned budget; cap exhaustion can no longer silently produce an unreviewed ship.
- **flow-swarm preparation** — first in-house consumer of the fn-136 structured-findings contract (the stall detector and ratchet read `findings.items` exactly as a downstream product would), proving the receipt boundary on our own machinery.

Design-principle fit: the detector is an unattended-trust rail (the sanctioned deterministic category), not model-weakness scaffolding; all flowctl additions are zero-judgment (burden-of-proof met); everything that weighs or judges (severity, prose-vs-behavior classification) stays with the models.

## Decision Context

Why trajectory-augmented count cap over the alternatives. **Raise-to-8 alone** doubles the worst case on stuck specs and was explicitly labeled interim in the docstring that shipped it. **Replace count with model-judged convergence** violates the load-bearing constraint that the agent can never extend its own gate, and asking the reviewer "another round?" hands it a budget decision it has no business owning. **Refund fix-induced-residue rounds** makes the classifier the loophole that swallows the cap — rejected; residue headroom comes from the raised cap, and trivial residue is instead prevented from blocking at all via the plan-surface outcome test. The chosen design keeps every fn-90/fn-131 property (deterministic counter, transport refunds, distinct exit codes, ESCALATE-not-retry) and adds only shorten-only terminals computed by flowctl from reviewer-emitted structured data — cross-model signal, not self-assessment, and it cannot self-grant because it never touches arithmetic. Gap-analysis decisions folded in: reset clears the hash baseline (reset and baseline are one clean-slate operation — anything else re-breaks the fn-155 recovery the guard was motivated by); `--force` is human-only and guard-blocked (otherwise a retry-with-force habit in an autonomous loop trivially defeats the guard); NEEDS_HUMAN writes a real `needs_human` status (drivers read status fields, not just exit codes — a silent `None` would leave state lying); hash failure fails open while findings-parse failure fails inert (a guard that blocks legitimate reviews on an I/O hiccup is worse than the waste it prevents; a detector that stalls on malformed data manufactures false escalations). Review-round-1 decisions: baseline invalidation is an **epoch bump**, never ledger mutation (`review_attempts` is append-only audit history); reservation state travels by **id-keyed metadata**, not FIFO (RP finalizes in a separate process, possibly out of order); the detector reads **spec-state findings digests**, not receipt files (receipts are `/tmp`-ephemeral and (type,id,mode)-scoped — a digest persisted at record time is the only representation that is durable AND counter-scoped AND backend/type-independent, and it doubles as the auditable trace of why a stall fired); completion hashes include the dispatched diff + criteria (completion verifies implementation against spec — spec+tasks alone would refuse legitimate re-reviews after implementation-only fixes); NEEDS_HUMAN exits 4 only from the outermost layer after all persistence (an early exit anywhere inside the recorder/finisher silently drops receipts). Per-surface divergence is deliberately confined to severity definitions and blocking contracts because the evidence showed the rubrics already diverge (0 of 8 numbered criteria shared) and the observed failures were calibration failures: plan reviews blocking on outcome-free prose (fn-155/153/156), impl review lacking a settled-plan clause, and the un-promptable PR bot over-weighted in flow-next (prose findings gating merges) while structurally ignored in flow-swarm (17/23 reviews post-merge). The bot stays a bounded-and-filtered safety net: scope via the trigger comment we control, blocking-ness via resolve-pr triage we control.
