## Goal & Context
<!-- scope: business -->
<!-- Goal & Context: 30% [user], 50% [paraphrase], 20% [inferred] -->

Add Cognition's Devin as a first-class flow-next host, covering Devin CLI and Devin Desktop, with Devin cloud documented as a partial surface. [user]

Devin CLI and Devin Desktop share one local agent harness. That harness installs Claude Code plugins as-is from a GitHub subdirectory, resolves the Claude manifest when no Devin manifest exists, loads every plugin agent as a subagent profile, interpolates skill arguments on a user slash invocation, offers a native blocking question tool, and runs background subagents while the parent continues. A plugin installed at personal scope reaches Desktop on another machine and cloud sessions without any local step. [paraphrase]

The live smoke found the plugin usable today but degraded in one way that matters: Devin ignores the plugin's command directory and honours the skills' user-invocable opt-out, so only five of thirty-three skills get a slash form, and the ones that do are spelled with the long skill name. The remaining skills, including plan, work, capture, and flow, are reachable only by natural language, and Devin's skill tool passes no arguments to a model-triggered skill. The autocomplete gap was observed on both CLI and Desktop. [paraphrase]

This is a documentation-and-manifest host addition in the shape of Grok Build, plus one small generated mirror. It is not an installer, and it is not a rewrite pass over skill prose. [user]

## Architecture & Data Models
<!-- scope: technical -->
<!-- Architecture & Data Models: 70% [paraphrase], 30% [inferred] -->

- **Devin plugin manifest.** A committed Devin-native manifest sits beside the Claude manifest and carries the same identity fields plus a skills-path list naming both the canonical skills directory and the generated mirror directory. Devin prefers its own manifest when present, so the Claude manifest is untouched. Verified in the lab copy: with this manifest every command name became a user-invocable `/flow-next:<name>` skill and the twenty-eight model-only skills stayed intact. [paraphrase]
- **Generated command mirror.** One generated skill directory per command wrapper, whose body is the wrapper's body and whose frontmatter is the wrapper's frontmatter plus a user-only trigger line. Regenerated by the same release step that regenerates the Codex mirror, idempotent, and asserted equal to the command directory by a test. Devin interpolates `$ARGUMENTS` on a user slash invocation, and the wrapper chains into the underlying skill with the arguments intact; verified with `--explain` through the flow wrapper and a full plan run in print mode. [paraphrase]
- **Agents.** Devin reads the shared agents directory and ignores a manifest agents-path key, so there is no Devin-only agents directory. Devin honours `model:` and a Claude-case `tools:` allowlist, ignores `disallowedTools` and `readonly`, and does not honour Devin-native `allowed-tools` inside agent files. [paraphrase]
- **flowctl resolution.** The skill-relative rung finds flowctl inside Devin's plugin cache; no environment variable is required. [paraphrase]
- **Host detection.** Devin exports exactly one variable to a skill's shell, its session-database variable. Setup keys on it, ahead of the Codex fallback and after the existing positive signals. [paraphrase]

## API Contracts
<!-- scope: technical -->
<!-- API Contracts: 100% [paraphrase] -->

- Install command, both CLI and cloud personal scope: `devin plugins install gmickel/flow-next#plugins/flow-next`. Local development install: the same command with `--local` and a path. [paraphrase]
- Host command form on Devin: `/flow-next:<name>` for every command wrapper, identical to Claude Code. The five already user-invocable skills keep their long form as well. [paraphrase]
- Headless invocation form documented for Devin: print mode with the prompt after `--`, because a prompt beginning with a slash is parsed as a path. [paraphrase]

## Edge Cases & Constraints
<!-- scope: technical -->
<!-- Edge Cases & Constraints: 80% [paraphrase], 20% [inferred] -->

- **Model pins fail hard.** A profile whose `model:` names a family the user's Devin plan cannot reach fails with a permission error instead of falling back. On the free plan, which offers one Cognition model, every pinned scout is unspawnable and only the two `inherit` agents run. [paraphrase]
- **Read-only is not carried by the current agent frontmatter.** An agent with only `disallowedTools` receives edit, write, and exec on Devin. Any allowlist containing exec can write through the shell. The only spelling that produced a hard read-only set was a Claude-case `tools:` list, which Devin maps to read, grep, and find and silently drops shell and web tools. [paraphrase]
- **Cloud is a partial surface.** Cloud sessions load plugin skills, rules, hooks, and MCP servers but not plugin subagents; fan-out there uses managed child sessions with no documented model pin. Plugin hooks are documented as best effort and are disabled in Desktop restricted mode. [paraphrase]
- **Slash invocation framing.** On a weak model a user slash invocation can be read as pasted documentation rather than an instruction; the mirror skills carry the wrapper's imperative preface, which is the mitigation. [paraphrase]
- **Existing consumers must not change.** Claude Code's plugin validator passes with the new files; Cursor's manifest lists explicit paths; the OpenCode scatter and the Codex mirror ignore unknown directories. [paraphrase]
- **Version bump.** The Devin manifest joins the list of manifests the bump step rewrites, and its description counts follow the same manual sweep as the others. [inferred]

## Decision Context
<!-- scope: both — conditionally substructured -->

### Motivation
<!-- scope: business -->

Devin is one of the most Claude-Code-compatible hosts available and its plugin install is a single command against the existing GitHub repository, so the marginal cost of first-class support is a manifest, a small mirror, detection, and docs. The user asked whether it could be a harness, ran the smoke on CLI and Desktop, and asked for the capture to include the docs site, the release process, and the agent-facing development docs. [paraphrase]

### Implementation Tradeoffs
<!-- scope: technical -->

- **Mirror over opt-out removal.** Dropping the user-invocable opt-out would expose every skill on Devin with no generated files, but each skill would then appear twice in the Claude Code slash menu and the Devin spelling would stay the long form. The mirror is twenty-nine tiny generated files under the existing sync step, so it is the smaller trade. [paraphrase]
- **Keep the agent posture.** Switching the read-only agents to a `tools:` allowlist would give Devin hard enforcement but would strip shell and MCP access from those agents on Claude Code, where several scouts depend on the shell. Keeping `disallowedTools` means Devin in-host review fails closed, which the review contract already requires when enforcement is unavailable. [inferred]
- **Fail-hard model pins are Devin's behaviour, not ours.** The existing cross-platform rule says pins map to host defaults off Claude Code; Devin instead refuses. Setup warns and the reach page states it; the fix belongs to the user's Devin plan or to a future per-host agent variant if Devin ever supports one. [paraphrase]
- **Detection on the one exported variable.** It is an internal-sounding name, but it is the only positive process-owned signal Devin gives a skill's shell, and the alternative is falling through to the Codex default. [paraphrase]
