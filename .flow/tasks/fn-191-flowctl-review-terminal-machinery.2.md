# fn-191-flowctl-review-terminal-machinery.2 Distribution integrity contract for the new package

## Description
Give the package the same distribution integrity contract the tracker package has: generated manifest, propagation through the existing mechanism to every channel and the committed dogfood copy, an integrity test, and both failure directions (stale install soft-fails; tampered manifest fails closed).

**Size:** M
**Files:** manifest generator (extend the existing one rather than adding a second); `scripts/gen_tracker_manifest.py` or its successor; `scripts/install-codex.sh`; `plugins/flow-next/skills/flow-next-setup/workflow.md`; ralph-init copies; `.flow/bin/` propagation; `plugins/flow-next/tests/` (new integrity test in the shape of `test_tracker_distribution`)
**Touches:** [scripts/gen_tracker_manifest.py, scripts/install-codex.sh, plugins/flow-next/skills/flow-next-setup/workflow.md, plugins/flow-next/skills/flow-next-ralph-init/**, plugins/flow-next/tests/**, .flow/bin/**]

### Approach
- Extend the EXISTING propagation and manifest mechanism - the installers already rsync a package dir; widen that path, never introduce a parallel one.
- Both failure directions are acceptance criteria, so implement both: a `.flow/bin` copy missing the package after a partial upgrade produces an actionable soft-fail naming the package (mirror the tracker package's message shape, never a bare traceback); a tampered or absent manifest makes the installers fail closed.
- Keep the manifest literal out of the host module's source (`test_no_per_command_hashing`); manifest checks live in the generator and installers only.
- Propagation recipe per the project instruction file (cp the module, rsync the package dirs excluding `__pycache__`, regenerate the manifest, sync-codex twice). Verify a clean tree afterwards.
- Windows matters here: the OS smoke matrix drives the real launcher and the installed layout, so a channel that forgets the package fails there rather than in the field.

### Investigation targets
**Required** (read before coding):
- `plugins/flow-next/tests/test_tracker_distribution.py` - the integrity-test shape to mirror, including its runtime smoke
- `scripts/gen_tracker_manifest.py` - the generator to extend
- `scripts/install-codex.sh` package-presence guard block - the fail-closed pattern already written for the tracker package

### Acceptance
- [ ] Manifest generated by the extended existing generator; no second mechanism introduced
- [ ] Package propagates to `.flow/bin/` and every install channel; integrity test asserts the distribution in the shape of the tracker package's
- [ ] Stale install missing the package → soft-fail naming the package and remedy; tampered or absent manifest → installers fail closed (both covered by tests)
- [ ] Manifest literal absent from the host module source (`test_no_per_command_hashing` green)
- [ ] OS smoke matrix green in CI, Windows included
