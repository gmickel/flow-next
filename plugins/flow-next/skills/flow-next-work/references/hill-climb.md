# Hill-climb route (gated reference)

> **Loaded only when** the spec's goal is one metric moved toward a target through repeated attempts (flow's hill-climb row). The worker reads it before the first change (worker Phase 1.5); on the bridged path the child is pointed at it. Other tasks never read it.

You own the metric and the experiment's integrity. The loop runs inside the one task work mints for the spec and replaces worker Phase 2's single change: each kept attempt is its own Phase 3 commit, and review (Phase 4) runs once over the kept commits at the end. Core discipline: one change, one measurement, keep or revert. Never stack untested changes, and never claim a win from reading the code.

1. **Set up the experiment.** Read the target from the spec. A spec with no target is the only missing information that stops the run: attended, ask once; unattended (`flow --auto`, `mode:autonomous`), `NEEDS_HUMAN`. The target is the human's; never invent, relax or reinterpret it. Everything else is yours to decide, taking the user's values wherever the spec or conversation gives them: ground the workload and pick a case that reproduces the complaint, then fix the metric, the direction that counts as better, an attempt floor (so a lucky early win cannot end the run), a budget, the runs per measurement and the smallest difference that counts.
2. **Build the harness, prove it, freeze it.** One repeatable command emits the metric as the median of N runs after discarded warm-ups, alternating best and candidate runs so drift hits both alike, and fails on a wrong output instead of scoring it. Prove it: a known-worse and a known-better throwaway change must rank around the baseline with gaps wider than the baseline's run-to-run spread, and a wrong-output change must be rejected. Revert the probes, then freeze: record the command and a `sha256` of the harness files and inputs, and re-check it before every measurement (a change invalidates earlier measurements: record a `break` row and prove it again against the current best). If no harness you can build separates the cases, or the noise is wider than the gap to the target, stop before any attempt and report why. Record the baseline and a green run of the regression gate (the tests that must keep passing; the spec's Quick commands when nothing else is named) before any change. A harness committed to the tree is one setup commit before the loop, named in the record.
3. **Open the ledger.** Work in `.flow/tmp/hill-climb/<spec-id>/` (gitignored), with a detached worktree of the current best (`git worktree add --detach <run-dir>/best HEAD`, moved to each new best). `ledger.md` starts with the setup from steps 1 and 2 (case, metric, direction, target, attempt floor, budget, runs per measurement, smallest difference, harness with its proof and hash, regression gate, baseline), written before the first attempt so the choices are fixed in advance, then one row per attempt:

   ```text
   | # | Family | Mechanism | Change | Before (median, range) | After (median, range) | Delta | Gate | Verdict | Reason | Commit |
   ```

   `Verdict` is `kept`, `reverted` or `inconclusive`. Rows that are not attempts carry `-` in `#`: `break`, `pivot` (a plateau changed the approach, with the reason) or `review-fix` (step 6).
4. **Loop, one hypothesis per attempt.** Read the ledger first, so a refuted idea is never retried unchanged. Ground the hypothesis in a profile or trace and name its mechanism ("the YAML parser loads at startup but only `export` uses it"); its family is one of delete, defer, reuse, coalesce, shrink, parallelise, represent, move, lighten or tune. Make one change and measure it against the current best. Keep it only when its median beats the best's by at least the smallest difference that counts and by more than the spread of either side's runs, and the regression gate is green; a simplification that holds the number may be kept too. Anything else is `inconclusive` (inside the noise) or `reverted` (worse, or a win that breaks the gate), and is reverted in full: restore touched files, remove created ones, and confirm `git status --porcelain` is empty, or stop, since every later measurement would be meaningless. A kept attempt is exactly one commit, `perf(<scope>): <mechanism> (hill-climb attempt <n>)`; the tree was clean before it and the ledger is gitignored, so `git add -A` stages only the attempt. Write the row whatever the verdict. Independent hypotheses may run in parallel, each in its own worktree, each kept only on its own measurement against the current best (re-measured if the best moved meanwhile). Correctness outranks the number: revert a win that breaks behaviour.
5. **Push past plateaus; stop honestly.** Three non-kept attempts in a row are a plateau, not a stop: change family, combine near misses, or re-profile, and write the pivot row. Stop when the target is met and the attempt floor reached, the budget is spent, the remaining ideas are marginal, or the harness breaks; record which. When the run stops short of the target, the task still completes honestly: before review, add the outcome to the task description (`flowctl task set-description`), which the reviewer reads, naming the stop rule, the gap, and that the target's R-ID is `deferred` (not met within the budget, gap carried to the PR). Review's SHIP rule accepts R-IDs `met` or `deferred`, so a SHIP on the kept commits carries the task through done and make-pr with the target shown unverified. The budget is never extended to satisfy a review.
6. **Verify, then record.** Before `flowctl done`, check `$(cat .flow/tmp/base_commit)..HEAD` against the ledger: one row per attempt; each kept row names exactly one commit touching only that attempt's files; no commit changes measured code without a kept row, except the named setup commit and review fixes, which get a `review-fix` row measured against the best and kept only when not worse by the smallest difference with the gate green; the final value is measured at the final head with the gate green there. Fix the record or the history before done. Then add this block, then the full ledger, to the done summary; a value that cannot be shown reads `unverified: <reason>`. make-pr summarizes the block in the PR briefing.

   ```text
   Hill climb:
   - metric: <metric> (<direction> is better); target <target>
   - baseline: <median> (<range>) | final: <median> (<range>) at <sha> | change: <signed percent>
   - attempts: <n> (kept <k>, reverted <r>, inconclusive <i>); floor <f>; budget <b>
   - kept commits: <sha> <subject>; ... (in order)
   - harness: <command>, sha256 <hash>; proof: worse <median>, baseline <median>, better <median>; wrong output rejected (<how>)
   - gate: <command> green | red at <final sha>
   - stop: <which stop rule>
   - target: met | unverified (<gap>)
   - best untried: <mechanism> (<family>)
   ```

   Pass the harness and gate commands to `done` as `--test` lines, plus `--test "hill-climb ledger: <n> attempts (kept <k>, reverted <r>, inconclusive <i>); <baseline> -> <final>"`. When memory is enabled, add one knowledge entry per mechanism that proved out or proved useless here (`flowctl memory add --track knowledge --category best-practices`, with the module and the measured delta), so the next climb starts from it.
