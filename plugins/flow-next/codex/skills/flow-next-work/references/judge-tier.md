# Judge at dispatch

Before each worker spawn, call `$FLOWCTL judge --preset tier --task <task-id> --json` once. Pass the explicit invocation model with `--explicit-model`, the routing block's fast model with `--fast-model`, and the role's pinned model with `--role-model` when present. Pass `--can-spawn-model` / `--can-bridge` only for host-verified reach. For a worker, also pass the effort facts from this host's reach page: `--effort-levels` (the levels the worker's spawn parameter accepts, lowest first; when the implementer goes over a bridge, including a routing-block implementer the worker will bridge, the bridge's levels) and `--default-effort` (the level a spawn without one runs at), `--explicit-effort` for an effort the invocation names (else one the routing block's implementer line names), and `--role-effort` when the worker role pins one, never for a routing-block implementer the worker will bridge (a role pin configures the in-host spawn, never a bridged child). Omit the levels when the spawn takes no effort parameter. Scouts still use `--state-file` for their actual bounded assignment (`task_title`, `task_body`, `acceptance`, `touches_count`, `has_quick_commands`, `repo`), with the same reach flags. Keep this result for the admission; never reroute a running worker or repeat the rolling decision at Phase 3c.

Use the returned `tier_line`, `spawn_model`, `spawn_effort`, and `implementer`. Set `spawn_model_args` to `{"model": result["spawn_model"]}` when non-null, otherwise `{}`, and add `"effort": result["spawn_effort"]` when that is non-null. The tier sets the effort: one level below the default for a confident mechanical answer, one above for a confident intelligent one, the default otherwise and without a judge answer; a requested or role-pinned effort wins, and an explicit model without an effort still takes the tier's effort. An explicit invocation model becomes `spawn_model` when the host can spawn it, goes over the bridge otherwise, and the `Tier:` line names it either way, with or without a judge key; pinned roles keep their model; without an explicit model, unavailable judge answers keep the session tier.

Expand `spawn_model_args` into the Task invocation so the selected model reaches its **`model` parameter** and the effort its **`effort` parameter**; on another host map each field to its equivalent spawn parameter. If the spawn rejects the effort, spawn once more without it and append `; effort <level> rejected, ran at default effort` to the `Tier:` line; never try a third level. A bridged implementer's effort arrives inside `implementer` as `<model> at <effort>`. Also pass `IMPLEMENTER: <implementer>` in the worker prompt when set. The prompt alone never selects a native model. For bridge-only reach, leave the native spawn unchanged and let worker Phase 1b resolve the `IMPLEMENTER` bridge. Scouts use the same selection with the host's read-only restrictions preserved and `role_model` set from the scout's role definition: a pinned role keeps its model and the `Tier:` line names it, since a spawn parameter would not change what runs; on bridge-only reach without a scout bridge, retain the existing scout model and state that limitation.

Print `tier_line` at dispatch and retain it in the task's done summary (or scout findings). After return append `(model: <actual_model>)` only when the returned model is backed by host execution metadata or the worker's actual bridge command. Without that evidence append `(model: not reported)`, so a run on another model than requested stays visible; never copy the requested model into the actual-model field. A long-running recommendation is advisory and creates no bridge or approval requirement.
