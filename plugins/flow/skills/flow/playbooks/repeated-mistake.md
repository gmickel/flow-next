# Repeated Mistake

Collect the recurring class, not the single instance: what the failures share and where an agent is when it makes them. There is no lessons store, and a lesson is kept only if it will still hold in six months and would change what a future agent does.

Propose an edit to whatever the next agent will actually read at the point the mistake happens—an instruction file, the run-and-prove page, standing criteria, or the spec template. Show the exact proposal and wait for the person's yes before editing anything.

Propose a check only when the mistake is mechanically detectable, the repo already has the tool for it, and the check is cheap; never propose new CI or test infrastructure. If a mistake returns after an instruction edit, treat that recurrence as the signal that a mechanical check is warranted.
